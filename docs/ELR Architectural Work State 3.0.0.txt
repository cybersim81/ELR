4. # ESTABLISHED ARCHITECTURAL DECISIONS

LearningObject.state:

Represents the editorial/domain lifecycle of the Learning Object.

It does not represent:

* Learning State;
* Mastery;
* Mastery State.

Learning State:

Represents the user's current learning-process condition with respect to
a Learning Object.

Learning State and Mastery State are distinct concepts.

Mastery State:

Represents the user's current mastery state with respect to a Learning
Object.

Mastery Evidence:

Represents observable evidence used by the Mastery Engine to evaluate
and update Mastery State.

Mastery Engine:

Interprets Mastery Evidence and produces Mastery State updates.

Knowledge:

The persistent knowledge model is centered on:

* Learning Object;
* Anchor;
* Knowledge Statement;
* Knowledge Category.

Knowledge Statement:

Represents the principal knowledge content of a Learning Object.

The approved architecture conceptually represents a Learning Object as:

```
Anchor + Knowledge Statement
```

A Learning Object represents one independent atomic knowledge.

A single source statement may produce multiple Learning Objects.

A new Knowledge Statement may update an existing Learning Object when
the underlying atomic knowledge remains the same.

Knowledge Statement is not an autonomous Domain Entity.

The current executable Domain representation is:

```
LearningObject
    statement: str
```

No autonomous KnowledgeStatement Domain Entity should be introduced
without a new explicit architectural decision.

6. # MASTERY STATE STATUS

Mastery State is formally specified by:

* Mastery State Specification 1.0.0;
* Mastery Engine Specification 1.0.0.

The Mastery State Specification has now been updated to define the
approved conceptual internal structure of Mastery State.

The approved structure is:

```
MasteryState
├── mastery_value
├── updated_at
└── source_evidence: Set<EvidenceReference>
```

`mastery_value`:

Represents the current mastery value and is modeled as a Value Object
of the Domain Model.

The concrete scale, numerical domain, thresholds, formulas, and scoring
algorithm remain outside the scope of this structural decision and
belong to the Mastery Engine.

`updated_at`:

Represents the point in time at which the current Mastery State was
updated.

`source_evidence`:

Represents a set of references to Mastery Evidence that the Mastery
Engine considers causally or evaluatively relevant to the determination
of the current Mastery State.

`source_evidence` is not the complete Evidence History.

It represents only the subset of observations considered relevant to
the current state.

Multiple Evidence references may therefore belong to the same Mastery
State when recurrence, repetition, or combination of observations is
relevant to its determination.

The Mastery State does not contain:

* the complete Evidence History;
* a persistence identity as a semantic Domain property;
* technical versioning as a necessary Domain property;
* a Learning Object revision identifier;
* a `confidence` property.

Persistence identity and technical versioning, if required, belong to
the corresponding persistence, infrastructure, or technical model.

The revision of the Learning Object against which a Mastery Evidence
was produced belongs to the context of that Evidence, not to the
intrinsic structure of Mastery State.

The Mastery State therefore represents the current mastery condition,
while the Evidence Model and Mastery Engine retain responsibility for
the observational and historical context used to determine that
condition.

IMPORTANT:

The above conceptual structure is approved, but this does not yet mean
that a concrete executable MasteryState Domain implementation or
Mastery persistence model is authorized.

Those implementation decisions remain subject to the remaining Mastery
work tracked in the Discrepancy Matrix.
