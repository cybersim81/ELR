================================================================================
Current Architectural State
================================================================================


L'English Learning Repository (ELR) è attualmente definito come:


Repository personale della conoscenza linguistica dell'utente.


Principio fondamentale:

L'ELR conserva esclusivamente conoscenza linguistica persistente consolidata.


L'ELR NON conserva:

- conversazioni;

- processi di apprendimento;

- ragionamenti dell'LLM;

- stati intermedi della KEP;

- evidenze operative;

- decisioni temporanee.


La conoscenza persistente è rappresentata attraverso:

- Learning Object;

- Anchor;

- Knowledge Statement;

- Knowledge Category;

- Learning State;

- Mastery.

Stato architetturale corrente:

Completato:

✓ Architecture Specification
✓ Architecture Decision Log
✓ Architecture Consistency Matrix
✓ Document ownership model
✓ Repository / Process / Interaction separation


In corso:

→ Riallineamento delle Specification secondo Architecture Consistency Matrix.

Obiettivo:

Verificare che ogni concetto abbia un documento proprietario già esistente
oppure una collocazione documentale approvata.


Non ancora finalizzato:

→ Component Specifications mancanti
→ Formalizzazione completa dei modelli operativi

Architectural Constraints
================================================================================


Durante la continuazione del progetto:


NON modificare il Domain Model ELR introducendo:


- Conversation Episode;

- Knowledge Candidate;

- Change Proposal;

- Evidence operative;

- processi KEP.


Questi appartengono al Process Model.


NON inserire nella Architecture Specification:


- algoritmi;

- strutture operative dettagliate;

- procedure interne.


NON creare nuovi concetti senza:


1.

identificazione del documento proprietario;


2.

valutazione nella Consistency Matrix;


3.

eventuale ADR se modifica l'architettura.

================================================================================
Session Restoration Rules
================================================================================


Durante il caricamento iniziale:


L'LLM deve:


- non proporre modifiche;

- non analizzare parzialmente;

- non introdurre miglioramenti spontanei;

- non modificare decisioni esistenti;


Deve esclusivamente:


- acquisire il contesto;

- confermare il caricamento;

- richiedere il documento successivo.


L'analisi progettuale riprende solo dopo il caricamento completo.

Final Principle
================================================================================


L'ELR deve rimanere un sistema documentariamente autoportante.

La continuità del progetto non dipende dalla conversazione.

La continuità è garantita da:

- documenti completi;

- ownership chiara;

- decisioni registrate;

- separazione tra architettura, processi e interazione.

================================================================================
Document Corpus Authority Rule
================================================================================

Il Document Ownership Registry costituisce la fonte autorevole per determinare
l'esistenza e la responsabilità dei documenti appartenenti al corpus ELR.

La presenza di un documento nel Document Ownership Registry indica che:

- il documento appartiene al corpus documentale ELR;

- il documento possiede una responsabilità documentale definita;

- il documento deve essere considerato disponibile durante il ripristino
  dell'ambiente progettuale.


Le sezioni che descrivono attività di creazione, revisione o riallineamento
documentale non devono essere interpretate come indicazione di inesistenza del
documento.

Tali sezioni indicano esclusivamente possibili attività evolutive sul documento
esistente.


Durante una nuova sessione progettuale:

- non devono essere inventati nuovi documenti non presenti nel Registry;

- non devono essere classificati come mancanti documenti presenti nel Registry;

- non devono essere introdotti nuovi nomi documentali per responsabilità già
  assegnate;

- eventuali nuovi documenti devono essere valutati attraverso la Document
  Ownership Model e la Architecture Consistency Matrix.


Principio:

Il Document Ownership Registry definisce il corpus documentale ELR.
Le interpretazioni operative devono rispettare il Registry come riferimento
primario.

Corpus Integrity Rule
================================================================================

Durante una nuova sessione progettuale:

Un documento può essere considerato parte del corpus ELR solo se:

- è presente nel Document Ownership Registry;

oppure

- è esplicitamente indicato come documento candidato da creare nella roadmap.


Concetti emersi durante l'analisi progettuale non devono essere trasformati
automaticamente in nuovi documenti.

Prima di introdurre una nuova Specification occorre verificare:

1.

se il concetto appartiene a un documento già esistente;


2.

se richiede una nuova ownership documentale;


3.

se la modifica deve essere registrata nella Architecture Consistency Matrix;


4.

se è necessario un aggiornamento della Roadmap.


Il termine "Specification" non implica automaticamente l'esistenza di un
documento.

La creazione di nuovi documenti richiede una decisione architetturale esplicita.
