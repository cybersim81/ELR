## 6. SESSION CHECKPOINT / CLOSURE PROTOCOL

The assistant should proactively monitor the working state for a clean
session boundary.

A **session closure point** may be proposed when:

* the current document or logical correction block is VERIFIED;
* no partially applied correction remains;
* the next task can be reconstructed deterministically from repository
  evidence;
* the current architectural state can be summarized without relying on
  conversational-only context;
* the continuity artifacts can accurately represent the next authorized
  action.

When these conditions are satisfied, the assistant should explicitly tell the
user that the session has reached a clean checkpoint and propose closing
the chat.

The assistant must not close the session automatically.

The user must explicitly approve the closure.

---

## 7. CHECKPOINT UPDATE PROTOCOL

When the user approves a proposed session closure:

1. identify which continuity artifacts actually require updating;
2. update only the necessary artifacts;
3. preserve the repository as the architectural source of truth;
4. record the verified working position;
5. record the next authorized action;
6. record any explicitly approved but not yet verified decisions;
7. verify the updated continuity artifacts in the repository;
8. report the checkpoint as ready for a new session.

The assistant must not claim that a continuity artifact was updated until the
repository has been successfully written and reread.
