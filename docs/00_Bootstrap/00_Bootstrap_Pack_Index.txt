# 00_Bootstrap_Pack_Index.txt

## ELR Bootstrap Pack

### Purpose

This Bootstrap Pack establishes the consolidated starting state for
implementation work on ELR.

It is a continuity and orientation package.

It does not replace the authoritative normative specifications, architecture
documents, ADRs, repository source code, tests, or implementation plans.

Where a conflict exists, the authoritative normative source prevails and this
Bootstrap Pack must be updated accordingly.

---

## Bootstrap Pack Contents

The Bootstrap Pack consists of:

1. `01_Normative_Baseline_State.txt`
2. `02_Implementation_Baseline_Inventory.txt`
3. `03_Implementation_Finding_Register.txt`
4. `04_End_to_End_Gap_Map.txt`
5. `05_Implementation_Alignment_Roadmap.txt`
6. `06_Session_Continuity_State.txt`
7. `07_Session_Prompt.txt`
8. `08_Current_Implementation_Checkpoint.txt`

The files are intentionally ordered from normative baseline through
implementation inventory, findings, end-to-end gaps, roadmap, continuity
state, session operating instructions, and the current implementation
checkpoint.

The operational IA-08 implementation plan is maintained separately under:

`docs/07_Implementation/ELR_IA08_Implementation_Conformance_Gap_Resolution_Plan_0.1.0.txt`

## Authority Order

The authority hierarchy is:

1. Authoritative normative specifications and ADRs
2. Repository source code and tests as implementation evidence
3. IA-08 implementation conformance plan
4. Current Implementation Checkpoint
5. This Bootstrap Pack as consolidated continuity state
6. Session-specific working notes

The Bootstrap Pack must never be used to override an authoritative
specification.

The IA-08 implementation plan must never be used to override an authoritative
normative specification.

## Session Operating Rule

A future session must:

1. Read the current implementation checkpoint.
2. Read the current roadmap.
3. Read the current IA-08 implementation plan.
4. Read the authoritative normative source relevant to the current finding.
5. Inspect repository implementation evidence.
6. Dispose the finding based on evidence.
7. Implement only a confirmed gap.
8. Run focused tests.
9. Run the complete test suite.
10. Record the resulting checkpoint.
11. Update continuity documentation only after verification.

Use:

`inspect → responsibility disposition → implement only confirmed gap → test → verify → checkpoint → next finding`
