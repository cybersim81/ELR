## ELR Bootstrap Pack

### Purpose

This Bootstrap Pack establishes the consolidated starting state for implementation work on ELR.

It is a continuity and orientation package.

It does not replace the authoritative normative specifications, architecture documents, ADRs, or repository source code.

Where a conflict exists, the authoritative normative source prevails and this Bootstrap Pack must be updated accordingly.

## IA-01 — Domain Semantic Alignment

`COMPLETE`

The following eight findings have been resolved:

### IA-001 — LearningObject Statement Representation

`RESOLVED`

LearningObject represents KnowledgeStatement explicitly as an immutable aggregate member / knowledge value.

### IA-002 — KnowledgeStatement Identity Semantics

`RESOLVED`

KnowledgeStatement has no autonomous identity, lifecycle, repository, or versioning boundary.

### IA-003 — Generic Version Entity

`RESOLVED`

Version identity is explicitly scoped to LearningObject through `learning_object_id`.

### IA-005 — LearningObject Version Number

`RESOLVED`

LearningObject no longer stores mutable Version state.

Immutable Version history represents historical knowledge state.

### IA-010 — Generic VersionRepository History

`RESOLVED`

Version history is retrieved using `learning_object_id`.

### IA-017 — Version Snapshot Representation

`RESOLVED`

Version snapshots preserve the structured KnowledgeStatement value.

### IA-018 — Application / Repository Version Boundary

`RESOLVED`

Application and repository Version history semantics are aligned around LearningObject.

### IA-019 — Version Snapshot Test Coverage

`RESOLVED`

Application tests verify Version creation, Version numbering, snapshot content, preservation of previous Versions, and resulting LearningObject state.

## IA-01 Closure Rule

The eight IA-01 findings listed above are closed.

They must not be reopened merely because later implementation work introduces persistence, infrastructure, or integration gaps.

They may only be reopened if new repository evidence demonstrates a direct contradiction with the authoritative normative corpus.

Any such contradiction must first be identified against the authoritative source before changing the Bootstrap Pack.

## Current LearningObject Lifecycle

The normative LearningObject lifecycle is:

Candidate
    ↓
Proposed
    ↓
Active
    ↓
Retired

`Reviewed`, `Approved`, and `Rejected` are not LearningObject lifecycle states.

They belong to the Change Proposal review process and must not be introduced into the LearningObject lifecycle.

---

## Versioning Boundary

LearningObject is the primary unit of knowledge versioning.

KnowledgeStatement is an aggregate member / knowledge value.

Version is immutable and explicitly belongs to LearningObject through `learning_object_id`.

Version history is distinct from operational Audit history.

Audit records must not be used as a substitute for immutable Version history.
