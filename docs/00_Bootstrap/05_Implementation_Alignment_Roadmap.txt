# 05_Implementation_Alignment_Roadmap.txt

## Implementation Alignment Roadmap

### Purpose

This roadmap converts the Implementation Baseline Inventory and End-to-End Gap Map into an ordered implementation sequence.

It is subordinate to the normative architecture.

### Guiding Rule

Resolve semantic deviations before materializing production persistence.

Do not encode a currently non-conformant domain representation into database schemas and repositories and then attempt to correct it later.

---

## Phase IA-01 — Domain Semantic Alignment

### Objective

Bring the domain representation into explicit agreement with the consolidated normative baseline.

### Scope

Resolve:

* IA-001 — LearningObject statement representation;
* IA-002 — KnowledgeStatement identity/value semantics;
* IA-003 — generic Version entity;
* IA-005 — LearningObject version semantics;
* IA-010 — generic VersionRepository history;
* IA-017 — Version snapshot representation;
* IA-018 — application/repository Version boundary;
* IA-019 — Version snapshot test coverage.

### Completed result

The domain and repository contracts now express LearningObject-centered knowledge versioning.

KnowledgeStatement is represented as an immutable aggregate member/value and has no autonomous persistence or versioning boundary.

Version history is explicitly scoped to LearningObject.

Version snapshots preserve the structured KnowledgeStatement value.

Application and repository Version history contracts are aligned.

### Gate

`IA-01 DOMAIN ALIGNMENT`

Status: `COMPLETE`

### Closure evidence

* Domain entities aligned;
* VersionRepository contract aligned;
* Application service aligned;
* in-memory Version repository aligned;
* Version snapshot semantics tested;
* no autonomous KnowledgeStatement repository introduced.

### Remaining work outside IA-01

Production persistence and repository integration remain pending and belong to subsequent implementation-alignment phases.
