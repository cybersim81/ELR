# ELR — Session Prompt
================================================================================

This document is the operational entry point for any new implementation
session in the ELR repository.

It provides the minimum authoritative context required to resume work without
reconstructing the project state from chat history.

The session must treat the repository contents, the normative corpus, and the
implementation documentation as the authoritative sources of truth.

Chat history is contextual only and must not override repository evidence or
the normative corpus.


================================================================================
## Session Operating Rules
================================================================================

1. Inspect before modifying.

2. Do not infer implementation state from documentation alone when repository
   evidence can be inspected directly.

3. Do not reopen a responsibility already marked RESOLVED / VERIFIED unless
   new authoritative or repository evidence demonstrates a regression,
   contradiction, or previously missed gap.

4. Do not replace historical checkpoints with newer implementation
   verification results. Historical checkpoints must remain identifiable as
   historical.

5. Every implementation change must be followed by focused verification and
   complete test-suite verification where applicable.

6. Implementation documentation must remain synchronized with verified
   repository state.

7. Work must proceed through controlled, evidence-based increments.

8. When a gap is identified, distinguish clearly between:
   - missing implementation;
   - partial implementation;
   - blocked implementation;
   - documentation-only inconsistency;
   - already-resolved responsibility.

9. Do not expand scope beyond the confirmed gap.

10. Preserve all previously verified E2E gates unless contradictory evidence
    is found.
