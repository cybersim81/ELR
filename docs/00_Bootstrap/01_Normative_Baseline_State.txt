### Consolidated Architectural Principles

The current baseline establishes the following principles relevant to the implementation alignment phase.

#### LearningObject

LearningObject is the primary domain aggregate and the primary unit of knowledge lifecycle and knowledge versioning.

Its stable identity persists across its immutable versions.

#### KnowledgeStatement

KnowledgeStatement is an aggregate member / knowledge value.

It does not constitute an autonomous aggregate.

It does not possess autonomous lifecycle or autonomous versioning semantics.

Its representation must therefore remain subordinate to the LearningObject aggregate.

#### Anchor

Anchor is a shared semantic reference.

It has its own stable identity and persistence boundary.

It is not part of the LearningObject aggregate.

LearningObject references Anchor rather than owning its lifecycle.

#### Version

LearningObject versioning is based on immutable historical versions.

Stable LearningObject identity and immutable Version history are distinct concepts.

Version history must not become a generic mechanism for autonomous versioning of arbitrary domain entities.

#### Lifecycle

The LearningObject lifecycle is normative and must reject invalid transitions.

The current LearningObject lifecycle flow is:

`Candidate → Proposed → Active → Retired`

`Reviewed`, `Approved`, and `Rejected` are not LearningObject lifecycle states.

They belong to the Change Proposal review lifecycle.

A modification to an Active LearningObject does not introduce an `Updated` state.

The modification is represented through a new immutable Version while the LearningObject remains in its appropriate lifecycle state.

The existence of a working lifecycle implementation does not by itself establish full normative conformance of persistence or version semantics.

#### Audit

Audit records represent operational history.

Audit history is distinct from immutable knowledge Version history.

Audit records must not be used as a substitute for Version persistence.

#### Evidence

Evidence is separate from the knowledge repository.

Evidence belongs to the Evidence Model and its dedicated processes.

It must not be conflated with LearningObject knowledge persistence or Version history.

#### Learning State

Learning State is persistent and user-specific, but it does not constitute linguistic knowledge.

It is distinct from the knowledge repository and from the LearningObject aggregate.

### IA-01 Domain Semantic Alignment Closure

The following implementation-alignment findings are explicitly closed by the current implementation state.

#### IA-001 — LearningObject Statement Representation

KnowledgeStatement is represented as an explicit aggregate member / knowledge value of LearningObject.

Status:

`RESOLVED`

#### IA-002 — KnowledgeStatement Identity Semantics

KnowledgeStatement has no autonomous identity, lifecycle, repository, or versioning boundary.

Status:

`RESOLVED`

#### IA-003 — Generic Version Entity

Version identity is explicitly scoped to LearningObject through `learning_object_id`.

Status:

`RESOLVED`

#### IA-005 — LearningObject Version Number

LearningObject no longer carries mutable Version state.

Immutable Version history is represented separately.

Status:

`RESOLVED`

#### IA-010 — Generic VersionRepository History

Version history is explicitly retrieved through `learning_object_id`.

Status:

`RESOLVED`

#### IA-017 — Version Snapshot Representation

Version snapshots preserve the structured KnowledgeStatement value.

Status:

`RESOLVED`

#### IA-018 — Application / Repository Version Boundary

Application and repository layers use the same LearningObject-centered Version history boundary.

Status:

`RESOLVED`

#### IA-019 — Version Snapshot Test Coverage

Application tests verify Version creation, Version history, snapshot content, Version numbering, and preservation of previous Versions.

Status:

`RESOLVED`
