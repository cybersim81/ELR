================================================================================
English Learning Repository (ELR)

IA-08-A01.1 Application Error Boundary
Implementation Change Set

Version: 0.1.0
Status: CONTROLLED IMPLEMENTATION
================================================================================


# 1. Objective
================================================================================

Implement the minimum Application Layer error boundary required to resolve
IA-08-A01.1.

The implementation shall:

* centralize Application errors;
* preserve Domain error ownership;
* translate InvalidStateTransition into InvalidOperation;
* normalize LearningObjectNotFound into EntityNotFound;
* preserve exception causes for Domain-to-Application translation;
* avoid changes to Domain behavior;
* avoid changes to persistence behavior.


================================================================================
# 2. Current Implementation
================================================================================

Current relevant structure:

app/
    application/
        services/
            learning_object_service.py

The current LearningObjectService defines LearningObjectNotFound locally.

The Domain LearningObject model defines InvalidStateTransition.

No centralized Application error taxonomy currently exists.


================================================================================
# 3. Files to Change
================================================================================

Create:

app/application/errors.py

Modify:

app/application/services/learning_object_service.py


================================================================================
# 4. Application Error Taxonomy
================================================================================

Create:

app/application/errors.py

The module shall define:

* ApplicationError;
* EntityNotFound;
* InvalidOperation;
* ValidationFailure;
* UnauthorizedOperation.


ApplicationError shall be the common Application Layer base exception.

The classes shall contain no HTTP-specific behavior.

They shall not depend on FastAPI or any infrastructure component.


================================================================================
# 5. LearningObjectService Changes
================================================================================

Remove the locally defined LearningObjectNotFound exception.

Import EntityNotFound and InvalidOperation from:

app.application.errors


The existing _get_or_raise() helper shall raise EntityNotFound.

Its semantic behavior must remain:

* repository returns no entity;
* Application Service raises application-level not-found error.


================================================================================
# 6. Domain Error Translation
================================================================================

Operations that invoke Domain behavior and may raise
InvalidStateTransition shall translate that Domain exception at the
Application boundary.

The affected LearningObjectService operations include:

* submit_for_review();
* approve();
* update_knowledge();
* retire().

The conceptual implementation is:

try:
    domain_operation()
except InvalidStateTransition as exc:
    raise InvalidOperation(...) from exc


The original Domain exception must remain available as the exception cause.


================================================================================
# 7. Error Message Requirements
================================================================================

Application error messages shall be stable and application-oriented.

They must not expose:

* SQL statements;
* database driver messages;
* HTTP implementation details;
* internal stack traces;
* infrastructure-specific object representations.


Messages should describe the failed application operation.

Examples:

EntityNotFound:

"Learning object not found."

InvalidOperation:

"Learning object cannot perform the requested operation."


The exact wording may follow existing project conventions if such conventions
already exist.


================================================================================
# 8. ValidationFailure
================================================================================

Define ValidationFailure as part of the Application Error taxonomy.

Do not introduce a new Domain-to-Application mapping for ValidationFailure in
this change.

No existing validation behavior shall be modified merely to exercise this
class.


================================================================================
# 9. UnauthorizedOperation
================================================================================

Define UnauthorizedOperation as part of the Application Error taxonomy.

Do not introduce authorization logic in this change.

Authorization remains a Security Layer responsibility.


================================================================================
# 10. Scope of Exception Translation
================================================================================

Only known Domain exceptions shall be translated.

Do not introduce:

except Exception:

or equivalent catch-all translation.

Unexpected infrastructure or programming errors must remain distinguishable
from known application failures.


================================================================================
# 11. Tests
================================================================================

Add focused tests for the Application Service.

At minimum verify:

## 11.1 Not Found

Given a missing Learning Object:

LearningObjectService.get()

raises:

EntityNotFound


## 11.2 Invalid Submission

Given a Learning Object for which submission is invalid:

LearningObjectService.submit_for_review()

raises:

InvalidOperation


The underlying cause must be:

InvalidStateTransition


## 11.3 Invalid Approval

Given a Learning Object for which approval is invalid:

LearningObjectService.approve()

raises:

InvalidOperation


The underlying cause must be:

InvalidStateTransition


## 11.4 Invalid Knowledge Update

Given an invalid lifecycle state:

LearningObjectService.update_knowledge()

raises:

InvalidOperation


The underlying cause must be:

InvalidStateTransition


## 11.5 Invalid Retirement

Given an invalid lifecycle state:

LearningObjectService.retire()

raises:

InvalidOperation


The underlying cause must be:

InvalidStateTransition


## 11.6 Successful Operations

Existing successful tests for:

* candidate creation;
* submission;
* approval;
* knowledge update;
* retirement;
* retrieval;
* history;

must continue to pass without behavioral changes.

    ->

================================================================================

semantics.

AC-009

AC-011

================================================================================
# 15. Stop Conditions
================================================================================

Stop and reassess if:

* LearningObjectService already contains an equivalent centralized error
  mechanism;
* existing tests require LearningObjectNotFound to remain publicly importable
  from learning_object_service;
* Domain behavior must be changed to perform the translation;
* a repository failure cannot be distinguished from a not-found result;
* API-specific behavior becomes necessary.
