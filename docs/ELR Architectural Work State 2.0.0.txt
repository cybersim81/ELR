4. # ESTABLISHED ARCHITECTURAL DECISIONS

LearningObject.state:

Represents the editorial/domain lifecycle of the Learning Object.

It does not represent:

* Learning State;
* Mastery;
* Mastery State.

Learning State:

Represents the user's current learning-process condition with respect to
a Learning Object.

Learning State and Mastery State are distinct concepts.

Mastery State:

Represents the user's current mastery state with respect to a Learning
Object.

Mastery Evidence:

Represents observable evidence used by the Mastery Engine to evaluate
and update Mastery State.

Mastery Engine:

Interprets Mastery Evidence and produces Mastery State updates.

Knowledge:

The persistent knowledge model is centered on:

* Learning Object;
* Anchor;
* Knowledge Statement;
* Knowledge Category.

Knowledge Statement:

Represents the principal knowledge content of a Learning Object.

The approved architecture conceptually represents a Learning Object as:

```
Anchor + Knowledge Statement
```

A Learning Object represents one independent atomic knowledge.

A single source statement may produce multiple Learning Objects.

A new Knowledge Statement may update an existing Learning Object when
the underlying atomic knowledge remains the same.

Knowledge Statement is not an autonomous Domain Entity.

It does not currently have:

* an independent UUID;
* an independent lifecycle;
* independent versioning;
* independent ownership.

The current executable Domain representation is:

```
LearningObject
    statement: str
```

The field `statement` is the current Domain representation of the
Knowledge Statement concept.

No autonomous KnowledgeStatement Domain Entity should be introduced
without a new explicit architectural decision.

5. # KNOWLEDGE STATEMENT STATUS

The Knowledge Statement discrepancy previously tracked by the Matrix
has been resolved.

The approved current representation is:

```
LearningObject.statement: str
```

The semantic concept remains Knowledge Statement, while its executable
Domain representation is currently a string field owned by
LearningObject.

The current architecture does not require a separate Value Object or
Entity for Knowledge Statement.

A future architectural decision may change this representation, but
such a change must be explicit and must update the affected
documentation before implementation.

The Persistence Mapping has been aligned with the current Domain
representation.

No autonomous KnowledgeStatement persistence relationship should be
introduced merely because an earlier persistence structure existed.

6. # MASTERY STATE STATUS

Mastery State is formally specified by:

* Mastery State Specification 1.0.0;
* Mastery Engine Specification 1.0.0.

These documents define Mastery State as the user's mastery state with
respect to a Learning Object.

The current Mastery specifications remain DRAFT and deliberately defer
the complete executable Domain contract.

The Mastery State Specification explicitly leaves implementation details
such as the following to future architectural decisions:

* Domain identity;
* persistence identity;
* temporal semantics;
* historical representation;
* versioning;
* evidence references;
* numerical representation;
* revision state.

Therefore:

Do NOT create another Mastery State Specification.

Do NOT add MasteryState to LearningObject.

Do NOT create Mastery persistence tables.

Do NOT infer final Mastery cardinality from the existing SQLAlchemy
model.

Do NOT treat the current implementation as authoritative for Mastery.
