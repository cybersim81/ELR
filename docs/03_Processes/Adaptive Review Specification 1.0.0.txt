================================================================================
Scopo
================================================================================

La Adaptive Review Specification definisce il processo responsabile della
selezione e dello scheduling adattivo delle Learning Activity all'interno
dell'English Learning Repository (ELR).

Adaptive Review utilizza lo stato di apprendimento e i segnali autorizzati
dal modello ELR per determinare quali Learning Activity proporre e quando
riproporle.

Adaptive Review non definisce le Learning Activity stesse.

Adaptive Review non modifica la conoscenza persistente.

Adaptive Review non calcola direttamente la Mastery.

Adaptive Review opera sopra i componenti proprietari della conoscenza,
della Mastery e delle Learning Activity.


================================================================================
Responsabilità del documento
================================================================================

Questo documento definisce:

- il concetto di Adaptive Review;
- la relazione tra Adaptive Review e Learning Activity;
- i criteri di selezione adattiva;
- i principi di scheduling;
- gli input autorizzati al processo;
- i confini con Mastery Engine, Evidence Model e Learning Activity.


Questo documento NON definisce:

- Learning Object;
- Knowledge Statement;
- Anchor;
- Mastery State;
- Evidence;
- Learning Activity;
- Exercise;
- algoritmi di generazione degli esercizi;
- algoritmi di calcolo della Mastery;
- procedure di modifica del Repository.


Queste responsabilità appartengono ai rispettivi componenti ELR.


================================================================================
Principio fondamentale
================================================================================

Adaptive Review risponde alla domanda:

"Quale Learning Activity dovrebbe essere proposta all'utente e quando?"


Non risponde alle domande:

"Quale conoscenza deve essere memorizzata?"

oppure:

"Quanto è competente l'utente?"


La prima appartiene ai processi di conoscenza.

La seconda appartiene al Mastery Engine.

Adaptive Review utilizza questi risultati per effettuare selezione e
scheduling adattivi.

ELR conserva la conoscenza persistente.

================================================================================
Adaptive Review Inputs
================================================================================

Adaptive Review riceve esclusivamente segnali prodotti o autorizzati dai
componenti proprietari del modello ELR.

Gli input principali sono:

- Learning Activity disponibili;
- Mastery State;
- segnali temporali autorizzati;
- Evidence rilevante, quando disponibile;
- contesto minimo necessario alla selezione;
- vincoli di scheduling definiti dal sistema.

Adaptive Review non modifica direttamente nessuno degli input ricevuti.


================================================================================
1. Learning Activity Input
================================================================================

Le Learning Activity costituiscono l'insieme delle attività candidate alla
selezione.

Adaptive Review può:

- valutare la loro eleggibilità;
- ordinarle secondo criteri adattivi;
- selezionare una o più attività;
- assegnare una priorità di revisione;
- determinare quando un'attività dovrebbe essere riproposta.


Adaptive Review non modifica la definizione della Learning Activity.

La struttura, il contenuto e la modalità di esecuzione della Learning Activity
rimangono di proprietà della Learning Activity Specification.


================================================================================
2. Mastery State Input
================================================================================

Il Mastery State rappresenta uno dei principali segnali utilizzati da
Adaptive Review.

Adaptive Review può utilizzare il Mastery State per:

- identificare conoscenze che richiedono revisione;
- determinare priorità relative;
- evitare ripetizioni non necessarie;
- favorire attività associate a conoscenze con padronanza insufficiente;
- determinare la necessità di una nuova esposizione.


Adaptive Review non calcola né modifica il Mastery State.

Il calcolo e l'aggiornamento della Mastery appartengono al Mastery Engine.


================================================================================
3. Evidence Input
================================================================================

Evidence può essere utilizzata come segnale complementare quando è disponibile
e autorizzata dal modello ELR.

Adaptive Review può utilizzare Evidence per:

- identificare attività recentemente eseguite;
- distinguere segnali recenti da segnali storici;
- supportare decisioni di revisione;
- evitare selezioni incoerenti con lo stato osservato.


Adaptive Review non crea, modifica o interpreta Evidence al di fuori delle
regole definite dal relativo Evidence Model.

Evidence rimane proprietà del componente Evidence Model.


================================================================================
4. Temporal Input
================================================================================

Adaptive Review può utilizzare informazioni temporali per determinare
l'opportunità della revisione.

I segnali temporali possono includere:

- tempo trascorso dall'ultima esposizione;
- tempo trascorso dall'ultima attività;
- intervallo previsto per una nuova revisione;
- priorità temporale;
- vincoli di sessione.


Il tempo è un segnale decisionale e non costituisce di per sé conoscenza
persistente.


================================================================================
5. Selection Decision
================================================================================

La selezione adattiva è il processo attraverso il quale Adaptive Review
determina quali Learning Activity sono candidate alla revisione.


Il processo concettuale è:

Candidate Learning Activities
        +
Mastery State
        +
Evidence signals
        +
Temporal signals
        +
System constraints
        |
        v
Adaptive Review Selection
        |
        v
Selected Learning Activity


La selezione deve essere spiegabile attraverso gli input autorizzati che
hanno determinato la decisione.


================================================================================
6. Selection Priority
================================================================================

Adaptive Review può assegnare una priorità relativa alle Learning Activity.

La priorità può essere determinata considerando:

- necessità di revisione;
- stato di Mastery;
- recency;
- tempo trascorso;
- evidenza recente;
- vincoli della sessione;
- diversità delle attività già selezionate.


La priorità non costituisce una nuova misura di Mastery.

Non deve essere utilizzata come sostituto del Mastery State.


================================================================================
7. Scheduling Decision
================================================================================

Lo scheduling determina quando una Learning Activity selezionata dovrebbe
essere proposta nuovamente.

Il processo concettuale è:

Selected Learning Activity
        +
Temporal signals
        +
Review priority
        +
System constraints
        |
        v
Adaptive Review Scheduling
        |
        v
Review Schedule


Lo scheduling può produrre:

- una finestra temporale;
- una priorità temporale;
- un ordine relativo;
- una condizione per la successiva revisione.


Lo scheduling non modifica la Learning Activity.


================================================================================
8. Separation of Selection and Scheduling
================================================================================

Selection e scheduling sono responsabilità correlate ma distinte.

Selection risponde alla domanda:

"Quale attività deve essere considerata per la revisione?"


Scheduling risponde alla domanda:

"Quando deve essere considerata nuovamente?"


Una decisione di scheduling non implica automaticamente una nuova selezione.

Una successiva selezione può utilizzare segnali temporali o di eleggibilità
derivati da un precedente Review Schedule, senza trasformare il Review
Schedule in una nuova Source of Truth.


================================================================================
9. Decision Constraints
================================================================================

Adaptive Review non deve selezionare una Learning Activity esclusivamente
perché:

- è recente;
- è frequente;
- è stata utilizzata in precedenza;
- appartiene a un Learning Object specifico;
- contiene una parola specifica.


La selezione deve essere giustificabile attraverso almeno un segnale
adattivo autorizzato.


================================================================================
10. Source of Truth Boundary
================================================================================

Adaptive Review produce decisioni di processo.

Non produce:

- nuova conoscenza;
- nuovi Anchor;
- nuovi Learning Object;
- nuovi Knowledge Statement;
- nuovi Evidence;
- nuovi Mastery State.


Le decisioni di Adaptive Review possono essere persistite solo secondo le
regole del sistema di persistenza e non diventano automaticamente conoscenza
ELR.

================================================================================
11. Mastery-Driven Review Policy
================================================================================

Adaptive Review utilizza il Mastery State come segnale per determinare la
necessità relativa di revisione.

La presenza di una Mastery insufficiente può aumentare la priorità di una
Learning Activity associata alla conoscenza interessata.

Adaptive Review non determina autonomamente il valore della Mastery.

La soglia, il significato e il calcolo della Mastery appartengono al
Mastery Engine.


================================================================================
12. Review Priority Classes
================================================================================

Adaptive Review può classificare le Learning Activity secondo una priorità
relativa di revisione.

Le classi concettuali possono includere:

- Review Required;
- Review Recommended;
- Review Optional;
- Not Currently Required.


Queste classi descrivono una decisione di processo.

Non costituiscono nuovi stati di Mastery.


================================================================================
13. Review Eligibility
================================================================================

Una Learning Activity è eleggibile per la revisione quando:

- è disponibile per la selezione;
- è compatibile con il relativo contesto di apprendimento;
- è associata a conoscenza rilevante per la revisione;
- non viola vincoli di sistema;
- non è esclusa da una condizione di scheduling attiva.


L'eleggibilità non implica necessariamente la selezione.

Una Learning Activity eleggibile può essere esclusa quando altre attività
presentano una priorità di revisione superiore.


================================================================================
14. Review Suppression
================================================================================

Adaptive Review può sopprimere temporaneamente la selezione di una
Learning Activity quando:

- è stata recentemente completata;
- è già presente in una sessione attiva;
- esiste una revisione equivalente già programmata;
- la relativa conoscenza non richiede attualmente revisione;
- esistono vincoli di scheduling incompatibili.


La soppressione è una decisione di processo.

Non modifica la Learning Activity né il relativo Mastery State.


================================================================================
15. Temporal Review Policy
================================================================================

Lo scheduling deve considerare il tempo come segnale di revisione.

Una Learning Activity può diventare nuovamente eleggibile quando:

- è trascorso l'intervallo minimo di revisione;
- è raggiunta una condizione temporale prevista;
- un nuovo segnale di apprendimento rende opportuna la revisione;
- una nuova selezione richiede una rivalutazione.


Gli intervalli temporali utilizzati da Adaptive Review devono essere
configurabili secondo le regole del sistema.

Adaptive Review non deve modificare retroattivamente gli eventi temporali
utilizzati come input.


================================================================================
16. Recency and Repetition
================================================================================

La recency può essere utilizzata per evitare una ripetizione eccessivamente
ravvicinata della stessa Learning Activity.

La recency non deve essere interpretata come misura di Mastery.

Una Learning Activity recentemente eseguita può essere nuovamente selezionata
quando esiste una ragione adattiva autorizzata.


La semplice ripetizione non costituisce di per sé una strategia adattiva.


================================================================================
17. Evidence-Aware Review
================================================================================

Quando Evidence è disponibile, Adaptive Review può utilizzarla per
determinare se una revisione è opportuna.

Evidence può aumentare, ridurre o non modificare la priorità di revisione
solo secondo regole autorizzate dal modello ELR.


Adaptive Review non può:

- creare una nuova Evidence;
- correggere una Evidence;
- ridefinire il significato di una Evidence;
- utilizzare Evidence come sostituto del Mastery State.


================================================================================
18. Session Constraints
================================================================================

La selezione deve rispettare i vincoli della sessione corrente.

I vincoli possono includere:

- numero massimo di attività;
- durata prevista della sessione;
- attività già completate;
- attività già programmate;
- diversità minima tra attività;
- ordine relativo richiesto dal sistema.


I vincoli di sessione possono modificare la selezione senza modificare la
priorità intrinseca delle conoscenze o il relativo Mastery State.


================================================================================
19. Diversity Constraint
================================================================================

Adaptive Review può utilizzare la diversità come criterio di selezione per
evitare sequenze didattiche eccessivamente ridondanti.

La diversità può riguardare:

- Learning Activity;
- conoscenze target;
- tipologia di attività;
- pattern di revisione;
- distribuzione temporale.


La diversità non deve diventare un nuovo criterio di Mastery.


================================================================================
20. Scheduling Recalculation
================================================================================

Uno scheduling precedente non impedisce una successiva rivalutazione.

Adaptive Review può ricalcolare la priorità o lo scheduling quando cambiano
gli input autorizzati, inclusi:

- Mastery State;
- Evidence rilevante;
- segnali temporali;
- disponibilità delle Learning Activity;
- vincoli della sessione.


Una rivalutazione non modifica retroattivamente le decisioni già registrate.


================================================================================
21. Determinism and Explainability
================================================================================

A parità di:

- Learning Activity disponibili;
- Mastery State;
- Evidence utilizzata;
- segnali temporali;
- vincoli di sistema;
- configurazione della policy;

Adaptive Review deve produrre una decisione riproducibile, salvo esplicita
configurazione di comportamento non deterministico.


Ogni decisione adattiva significativa deve poter essere ricondotta agli
input e ai criteri che l'hanno determinata.


================================================================================
22. Policy Boundary
================================================================================

La Adaptive Review Policy definisce criteri di selezione e scheduling.

Non definisce:

- nuove metriche di Mastery;
- nuovi tipi di Evidence;
- nuove Learning Activity;
- nuove categorie di conoscenza;
- nuovi esercizi;
- nuove regole grammaticali.


Quando una decisione richiede una nuova responsabilità di dominio o di
processo, tale responsabilità deve essere assegnata al componente ELR
appropriato invece di essere assorbita dalla Adaptive Review Policy.

================================================================================
23. Persistence Boundary
================================================================================

Adaptive Review può produrre decisioni di selezione e scheduling come
artefatti di processo.

Tali artefatti possono essere persistiti quando richiesto dal sistema.

La persistenza di una decisione di Adaptive Review non la trasforma in:

- conoscenza ELR;
- Mastery State;
- Evidence;
- Learning Activity;
- Source of Truth indipendente.


Qualsiasi modello persistente necessario alla registrazione delle decisioni
deve appartenere al componente ELR responsabile della relativa persistenza.


================================================================================
24. Review Decision Record
================================================================================

Quando una decisione di Adaptive Review viene registrata, il record dovrebbe
essere riconducibile almeno a:

- Learning Activity selezionata;
- timestamp della decisione;
- policy/configurazione utilizzata;
- segnali principali considerati;
- priorità assegnata, quando presente;
- scheduling prodotto, quando presente.


Il record deve consentire di ricostruire il motivo della decisione senza
duplicare o ridefinire i dati proprietari dei componenti sorgente.


================================================================================
25. Auditability
================================================================================

Le decisioni adattive significative devono essere auditabili.

L'audit deve consentire di determinare:

- quali input sono stati utilizzati;
- quale configurazione era attiva;
- quale decisione è stata prodotta;
- quando la decisione è stata prodotta;
- quale Learning Activity è stata selezionata o schedulata.


L'audit non deve richiedere la duplicazione integrale dei dati proprietari
degli altri componenti.


================================================================================
26. Configuration Versioning
================================================================================

Una decisione adattiva deve essere associabile alla versione della policy
o configurazione che l'ha prodotta.

Una modifica della configurazione non deve retroattivamente modificare
il significato storico delle decisioni già registrate.


Decisioni prodotte con configurazioni differenti devono rimanere
distinguibili quando tale distinzione è necessaria per audit o riproducibilità.


================================================================================
27. Failure Handling
================================================================================

Adaptive Review deve gestire esplicitamente i casi in cui gli input
necessari non siano disponibili, validi o sufficientemente aggiornati.


Quando un input critico non è disponibile, Adaptive Review deve:

- evitare di inventare il valore mancante;
- evitare di modificare il componente proprietario dell'input;
- applicare, quando prevista, una strategia di fallback autorizzata;
- oppure non produrre una decisione adattiva.


Un fallback non deve essere interpretato come una nuova misura di Mastery.


================================================================================
28. Invalid or Stale Inputs
================================================================================

Un input può essere considerato non utilizzabile quando:

- è formalmente invalido;
- è incompatibile con la versione attesa;
- è temporalmente obsoleto oltre i limiti autorizzati;
- è incoerente con i vincoli del sistema.


Adaptive Review non deve correggere autonomamente un input proprietario di
un altro componente.

L'input deve essere rigettato, ignorato o gestito attraverso un fallback
esplicitamente autorizzato.


================================================================================
29. No Eligible Activity
================================================================================

Quando nessuna Learning Activity soddisfa i criteri di eleggibilità,
Adaptive Review non deve produrre una selezione artificiale.


Il risultato può essere:

- nessuna attività selezionata;
- richiesta di rivalutazione futura;
- fallback esplicitamente configurato.


L'assenza di una selezione è un risultato valido del processo.


================================================================================
30. Conflicting Signals
================================================================================

Quando segnali autorizzati producono indicazioni divergenti, Adaptive Review
deve applicare una priorità determinata dalla policy configurata.


Adaptive Review non deve risolvere il conflitto modificando:

- Mastery State;
- Evidence;
- Learning Activity;
- Knowledge Object.


Il conflitto deve rimanere spiegabile attraverso i criteri applicati.


================================================================================
31. Reproducibility
================================================================================

Una decisione storica deve poter essere interpretata rispetto alla policy,
alla configurazione e agli input disponibili al momento della decisione.


La riproduzione di una decisione non richiede necessariamente la riproduzione
dell'intero sistema ELR, ma deve utilizzare gli stessi input e la stessa
configurazione rilevanti per la decisione.


Quando gli input storici non sono più disponibili, il sistema deve distinguere
tra:

- decisione storicamente registrata;
- decisione attualmente ricalcolabile.


Le due condizioni non devono essere confuse.


================================================================================
32. Idempotency
================================================================================

La ripetizione della stessa richiesta di Adaptive Review con gli stessi input,
la stessa configurazione e lo stesso contesto non deve produrre duplicazioni
indesiderate di decisioni o scheduling.


Quando il sistema richiede esplicitamente una nuova rivalutazione, questa
deve essere distinguibile dalla ripetizione della stessa richiesta.


================================================================================
33. Safety Boundary
================================================================================

Adaptive Review non deve eseguire automaticamente operazioni che modifichino
la Source of Truth di altri componenti.


In particolare, una decisione Adaptive Review non può:

- modificare Learning Object;
- modificare Mastery State;
- modificare Evidence;
- modificare Learning Activity;
- creare conoscenza persistente.


Qualsiasi modifica necessaria deve essere eseguita dal componente owner
attraverso il relativo processo autorizzato.


================================================================================
34. Normative Rules
================================================================================

Le seguenti regole sono normative per Adaptive Review:

AR-001:
Adaptive Review seleziona e schedula Learning Activity.

AR-002:
Adaptive Review non calcola né modifica Mastery.

AR-003:
Adaptive Review non crea né modifica Evidence.

AR-004:
Adaptive Review non modifica la definizione delle Learning Activity.

AR-005:
Adaptive Review non introduce una nuova Source of Truth.

AR-006:
Una decisione adattiva deve essere riconducibile agli input e alla policy
che l'hanno prodotta.

AR-007:
L'assenza di una Learning Activity eleggibile è un risultato valido.

AR-008:
Gli input mancanti o invalidi non devono essere inventati o corretti
da Adaptive Review.

AR-009:
Le decisioni storiche devono rimanere distinguibili dalle rivalutazioni
successive.

AR-010:
Una modifica della policy non deve alterare retroattivamente il significato
delle decisioni già registrate.


================================================================================
Principi conclusivi
================================================================================

Adaptive Review è un processo derivato che utilizza segnali autorizzati
dall'ELR per selezionare e schedulare Learning Activity.

La sua responsabilità termina nella decisione di revisione.

Non assume ownership della conoscenza, della Mastery, dell'Evidence,
delle Learning Activity o degli esercizi.

Le decisioni Adaptive Review devono rimanere spiegabili, auditabili e
riproducibili entro i limiti degli input e della configurazione disponibili.

Adaptive Review non introduce una nuova Source of Truth.
