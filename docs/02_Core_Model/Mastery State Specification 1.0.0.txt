Mastery State Specification

Version:
1.0.0

Status:
APPROVED

Scope:
Definition of the Mastery State Domain Model

Dependencies:

* ELR Architecture Specification
* ELR Architecture Decision Log
* Evidence Model Specification
* Mastery Engine Specification

================================================================================

1. Purpose
   ================================================================================

This specification defines the Domain Model representation of the Mastery State.

The Mastery State represents the current mastery of a specific User with
respect to a specific Learning Object.

The Mastery State is User-specific and Learning Object-specific.

The Mastery State is not an intrinsic property of the Learning Object and does
not belong to the Learning Object aggregate boundary.

This specification defines the conceptual structure and semantic
responsibilities of the Mastery State.

It does not define:

* mastery evaluation algorithms;
* evidence generation;
* evidence classification;
* mastery update policies;
* persistence implementation;
* ORM mappings;
* database structures.

================================================================================
2. Architectural Position
=========================

The Mastery State belongs to the Learning Assessment domain.

Its architectural responsibility is to represent the authoritative current
state of mastery resulting from the interpretation of relevant Mastery
Evidence.

The Mastery Engine is responsible for interpreting Mastery Evidence and
updating the Mastery State.

Evidence production and Evidence interpretation are therefore separate
responsibilities.

The Mastery State does not determine its own evolution.

================================================================================
3. Mastery State Structure
==========================

The approved Domain Model structure of MasteryState is:

```
MasteryState
├── mastery_value
├── updated_at
└── source_evidence: Set
```

These are the complete semantic components of the Mastery State.

No additional semantic state property is introduced by this specification.

================================================================================
4. mastery_value
================

mastery_value represents the current mastery level of the User with respect to
the Learning Object.

mastery_value is a Value Object.

Its internal representation and allowed value space are defined by the
Mastery Value domain definition.

The Mastery State contains the current mastery value produced by the Mastery
Engine.

The Mastery State does not contain the algorithm used to calculate or update
mastery_value.

================================================================================
5. updated_at
=============

updated_at represents the timestamp associated with the current Mastery State.

updated_at belongs to the Mastery State because it describes when the current
state was established or last updated.

updated_at is part of the semantic state representation.

It is not a persistence-specific metadata field.

================================================================================
6. source_evidence
==================

source_evidence is a Set of Evidence relevant to the determination of the
current Mastery State.

The set identifies the Evidence that supports the current state represented by
the Mastery State.

source_evidence is not the complete historical record of Evidence associated
with the User and Learning Object.

Evidence History belongs to the Evidence Model and the processes responsible
for producing and managing Evidence.

The Mastery State therefore contains only the Evidence references required to
identify the sources relevant to the current state.

================================================================================
7. Evidence Boundary
====================

Evidence and Mastery State have distinct architectural responsibilities.

Evidence represents information produced by an observable learning event or
assessment process.

The Mastery State represents the resulting current state of mastery.

The Mastery Engine interprets Evidence and determines the resulting Mastery
State.

Therefore:

```
Evidence
    ↓
Mastery Engine
    ↓
Mastery State
```

Evidence does not directly modify the Mastery State.

The Evidence Model remains responsible for defining the semantics and
classification of Evidence.

================================================================================
8. Learning Object Version Boundary
===================================

The revision or version of a Learning Object is not a property of the
Mastery State.

Learning Object revision belongs to the context of the Evidence from which
the relevant observation or assessment originated.

The Mastery State therefore does not contain:

* Learning Object revision;
* Learning Object version;
* a snapshot of the Learning Object;
* a persistence version identifier.

================================================================================
9. Confidence Boundary
======================

The Mastery State does not contain a separate confidence property.

No `confidence` field is introduced as an independent component of the
Mastery State.

Questions concerning reliability, quality, or interpretation of Evidence
belong to the Evidence Model and Mastery Engine responsibilities rather than
constituting an additional semantic state variable of MasteryState.

================================================================================
10. Persistence Boundary
========================

Persistence identity and technical versioning are not semantic properties of
the Mastery State Domain Model.

The Domain Model must therefore not introduce persistence-specific fields
merely to support database identity, ORM mapping, or technical versioning.

Persistence concerns belong to the Persistence Model and Persistence Layer.

The Persistence Layer must not redefine the semantic structure of the
Mastery State.

================================================================================
11. Historical Evidence Boundary
================================

The Mastery State is a representation of current state, not a historical
Evidence archive.

The following distinction is therefore normative:

```
Evidence History
    ↓
Evidence Model / Process responsibilities

Current Mastery State
    ↓
MasteryState
```

source_evidence identifies the Evidence relevant to the current state.

It does not represent the complete chronological history of all Evidence.

================================================================================
12. Domain Invariants
=====================

A Mastery State:

* is associated with one specific User;
* is associated with one specific Learning Object;
* contains one current mastery_value;
* contains the timestamp of the current state;
* identifies the Evidence relevant to the current state;
* does not contain the complete Evidence History;
* does not contain Learning Object revision information as a Mastery State
  property;
* does not contain persistence identity or technical versioning as semantic
  properties;
* does not contain an independent confidence property.

The Mastery State must remain independent of persistence technology.

================================================================================
13. Responsibility Boundary
===========================

The responsibilities are divided as follows:

Domain Model

Defines:

* the MasteryState structure;
* the semantic meaning of its components;
* its domain invariants.

Evidence Model

Defines:

* Evidence semantics;
* Evidence classification;
* Evidence references;
* Evidence History responsibilities.

Mastery Engine

Defines:

* Evidence interpretation;
* mastery evaluation;
* mastery update policy;
* transitions of the Mastery State.

Persistence Model

Defines:

* persistence representation;
* mapping;
* storage concerns;
* technical identity and versioning mechanisms where required.

No layer may silently transfer responsibilities belonging to another layer.

================================================================================
14. Architectural Consistency
=============================

This specification formalizes the approved architectural decision recorded as
#18.8 in the ELR Core Model Discrepancy Matrix.

The approved Mastery State structure is:

```
MasteryState
├── mastery_value
├── updated_at
└── source_evidence: Set
```

The following decisions are therefore normative:

* mastery_value is a Value Object;
* updated_at belongs to the Mastery State;
* source_evidence is the set of Evidence relevant to the determination of
  the current state;
* source_evidence is not the complete Evidence History;
* Learning Object revision belongs to the Evidence context, not to the
  Mastery State;
* persistence identity and technical versioning are not semantic properties
  of the Domain Model;
* no separate confidence property is introduced.

================================================================================
15. Implementation Boundary
===========================

This specification defines the Domain Model only.

It does not authorize or define a concrete persistence implementation.

Implementation of the Mastery State remains subject to the architectural
boundaries defined by the Mastery Engine, Evidence Model, and Persistence
specifications.

Any implementation must preserve the approved Domain Model structure and must
not introduce persistence-driven semantic properties into MasteryState.

================================================================================
16. Status
==========

The Mastery State internal structure defined by this specification is
APPROVED.

The specification formalizes the architectural decision recorded as #18.8 in
the ELR Core Model Discrepancy Matrix.

No unresolved conceptual decision concerning the internal structure of the
Mastery State is introduced by this specification.
