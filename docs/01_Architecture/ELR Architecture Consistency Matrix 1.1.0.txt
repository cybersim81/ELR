Scopo
================================================================================

La Architecture Consistency Matrix definisce la relazione tra i concetti
architetturali ELR, i documenti che li descrivono e il livello di dettaglio
appropriato.

La matrice viene utilizzata come strumento di controllo durante la creazione,
revisione ed evoluzione della documentazione ELR.

Principio guida:

Ogni concetto deve avere un documento proprietario principale.

Gli altri documenti possono riferirsi al concetto, ma non duplicarne la
definizione completa.

La matrice non definisce il comportamento dei componenti,
ma verifica che ogni responsabilità progettuale sia assegnata
al documento appropriato.

Legenda
================================================================================


✓ = definizione primaria presente nel documento proprietario.

R = riferimento al concetto senza ridefinizione completa.

Il documento proprietario è l'unico documento autorizzato a definire:

- significato completo del concetto;

- responsabilità;

- comportamento interno;

- regole operative.


Gli altri documenti possono utilizzare il concetto esclusivamente tramite
riferimento architetturale.

================================================================================
Regole di ownership documentale
================================================================================


1. Architecture Specification (AS)

Responsabilità:

Definire:

- componenti architetturali;

- responsabilità;

- confini;

- relazioni tra sistemi;

- principi fondamentali.


Non deve contenere:

- algoritmi;

- strutture operative dettagliate;

- procedure interne dei componenti.


-------------------------------------------------------------------------------


2. Component Specifications

Responsabilità:

Definire il funzionamento interno di un componente.


Esempi:

- KEP Specification;

- Evidence Model Specification;

- Mastery Engine Specification;

- Learning Review Specification;

- Anchor Specification;

- Learning Object Specification;

- Learning State Specification;

- Phrasebook Specification;

- Exercise System Specification.


Contengono:

- modelli operativi;

- strutture dati;

- criteri decisionali;

- flussi interni.


-------------------------------------------------------------------------------


3. Architecture Decision Log (ADR)

Responsabilità:

Definire il motivo delle scelte architetturali.


Contiene:

- problema;

- alternative considerate;

- decisione;

- conseguenze.


Non contiene:

- specifiche operative aggiornate.

-------------------------------------------------------------------------------

4. Document Ownership Rule


Ogni concetto architetturale deve rispettare:


- un solo documento proprietario;

- riferimenti negli altri documenti;

- assenza di definizioni duplicate.


La Architecture Consistency Matrix costituisce il controllo formale
dell'assegnazione delle responsabilità documentali.


================================================================================
Criterio finale di consistenza
================================================================================


Una modifica architetturale è considerata coerente quando:


- ogni concetto possiede un documento proprietario;

- gli altri documenti mantengono solamente riferimenti;

- la Architecture Specification contiene esclusivamente responsabilità
  architetturali;

- gli ADR descrivono motivazioni e conseguenze delle decisioni;

- le Specification descrivono comportamento interno e dettagli operativi;

- i sistemi derivati dipendono esclusivamente dal repository ELR;

- non esistono duplicazioni semantiche tra documenti.
