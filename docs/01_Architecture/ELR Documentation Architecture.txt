Document Header Standard
================================================================================

All ELR documentation artifacts MUST follow a common header structure.

The document header provides:
- document identification;
- version control;
- lifecycle status;
- architectural ownership;
- dependency traceability.

The mandatory header structure is:

================================================================================
English Learning Repository (ELR)

<Document Title>

Version: X.Y.Z
Status: <STATUS>
================================================================================

Document Identity

Document Type:
<Architecture Document | Specification | Process Document | Governance Document>

Purpose:
<Short description of the document responsibility>

Dependencies:
- <Required ELR documents>

Maintained By:
<Responsible ELR domain or governance entity>

================================================================================

Header Rules

1. The version declared inside the document MUST match the document filename.

2. Version numbers MUST follow semantic versioning:
   - MAJOR: architectural breaking changes;
   - MINOR: compatible additions;
   - PATCH: corrections and clarifications.

3. Every document MUST declare its lifecycle status.

Allowed lifecycle statuses:

- DRAFT
- REVIEW
- APPROVED
- BASELINE
- DEPRECATED

4. Archived documents MUST preserve their original headers and MUST NOT be
modified after archival.

5. Current documents MUST never depend on archived versions.

================================================================================
Document Lifecycle Management
================================================================================

ELR documents progress through controlled lifecycle states.

DRAFT:
Document under active development.

REVIEW:
Document submitted for architectural or domain review.

APPROVED:
Document accepted as valid and usable.

BASELINE:
Document represents an official architectural reference point.

DEPRECATED:
Document remains available for historical purposes but is no longer active.

Lifecycle transitions MUST be recorded through the Architecture Decision Log
when they affect architectural consistency.

================================================================================
Scopo
================================================================================

Questo documento definisce l'architettura del corpus documentale
dell'English Learning Repository (ELR).

La Documentation Architecture stabilisce:

- come è organizzata la documentazione;

- quali documenti esistono;

- le responsabilità di ciascun documento;

- il principio di ownership dei concetti;

- le regole che evitano duplicazioni e incoerenze.

La Documentation Architecture non definisce il modello ELR.

Definisce esclusivamente l'organizzazione della documentazione.


================================================================================
Principi fondamentali
================================================================================


## DOC-001 — Single Source of Truth
================================================================================

Ogni concetto architetturale possiede un unico documento proprietario.

Gli altri documenti possono fare riferimento al concetto ma non devono
ridefinirlo.


================================================================================
## DOC-002 — Responsibility Separation
================================================================================

Ogni documento descrive esclusivamente le responsabilità del proprio dominio.

Le definizioni non devono essere duplicate tra documenti differenti.


================================================================================
## DOC-003 — Progressive Detail
================================================================================

L'architettura documentale procede dal generale allo specifico.

I documenti di livello superiore descrivono i principi.

I documenti di livello inferiore descrivono il funzionamento dei singoli
componenti.

Document Design Principle
================================================================================

Il corpus documentale segue una gerarchia stabile.

Architecture Specification

descrive cosa esiste.

Domain Specifications

descrivono il modello persistente.

Process Specifications

descrivono il comportamento dei processi.

Platform Specifications

descrivono l'infrastruttura.

Architecture Decision Log

descrive perché una decisione è stata presa.

Documentation Index

descrive dove trovare ogni documento.

Architecture Baseline

identifica l'insieme ufficiale delle specifiche che costituiscono la baseline architetturale corrente.

Questa separazione consente l'evoluzione indipendente dei singoli documenti
preservando la coerenza dell'intero corpus.


================================================================================
Principio conclusivo
================================================================================

La Documentation Architecture rappresenta la struttura ufficiale della
documentazione ELR.

Ogni concetto possiede un unico documento proprietario.

Ogni documento ha una responsabilità chiaramente delimitata.

L'intero corpus documentale costituisce una rappresentazione coerente,
modulare ed evolutiva dell'architettura dell'English Learning Repository.
