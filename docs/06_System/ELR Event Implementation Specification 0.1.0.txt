================================================================================
Scopo
=====

La ELR Event Implementation Specification definisce la prima implementazione
del modello eventi dell'English Learning Repository.

Gli eventi rappresentano fatti avvenuti nel sistema.

Gli eventi:

* non comandano il sistema;
* non sostituiscono le API;
* non contengono logica applicativa.

================================================================================
Event Principles
================

EVENT-IMPLEMENTATION-001 — Facts Only

Gli eventi descrivono eventi già completati.

EVENT-IMPLEMENTATION-002 — Immutable Events

Un evento pubblicato non viene modificato.

EVENT-IMPLEMENTATION-003 — Domain Origin

Gli eventi significativi originano dal dominio o dall'application layer.

EVENT-IMPLEMENTATION-004 — Loose Coupling

I consumer non devono conoscere il produttore interno dell'evento.

================================================================================
Event Envelope
==============

Ogni evento utilizza una struttura comune coerente con l'ELR Event Model
Specification:

{

"event_id": "uuid",

"event_type": "string",

"event_source": "string",

"entity_id": "uuid",

"entity_type": "string",

"timestamp": "datetime",

"version": "integer",

"payload": {}

}

event_id identifica univocamente l'evento.

event_type identifica il tipo di fatto rappresentato.

event_source identifica il componente che ha prodotto l'evento.

entity_id identifica l'aggregate o l'entità a cui il fatto si riferisce.

entity_type identifica il tipo dell'aggregate o dell'entità.

timestamp identifica l'istante di registrazione dell'evento.

version identifica la versione dello schema dell'evento.

payload contiene esclusivamente le informazioni necessarie a rappresentare
il fatto avvenuto.

================================================================================
Event Envelope / Persistence Mapping
====================================

L'Event Envelope rappresenta il contratto dell'evento nel livello
di integrazione.

Il Transactional Event Record rappresenta la forma persistita dell'evento
destinata alla successiva pubblicazione.

I due livelli non richiedono una corrispondenza uno-a-uno dei campi.

Mapping:

event_id

→ event_records.id

event_type

→ event_records.event_type

event_source

→ event metadata associato al Transactional Event Record

entity_id

→ event_records.aggregate_id

entity_type

→ event_records.aggregate_type

timestamp

→ event_records.occurred_at

version

→ event schema metadata persistito associato al Transactional Event Record

payload

→ event_records.payload

Il valore di event_source deve essere preservato nella persistenza del
Transactional Event Record e deve rimanere disponibile per la successiva
pubblicazione dell'evento.

Il valore di version deve essere preservato nella persistenza del
Transactional Event Record e deve rimanere disponibile per la successiva
pubblicazione e interpretazione dell'evento.

Non è necessario che event_source o version siano colonne dedicate nella
tabella event_records, purché siano persistiti in metadata associati al
Transactional Event Record.

ChangeProposalApproved
======================

Descrizione:

Una Change Proposal è stata approvata dalla Learning Review secondo
le regole del Review e del Lifecycle Model.

Producer:

LearningReview / Application Service

Payload:

{

"change_proposal_id": "uuid",

"learning_object_id": "uuid",

"review_id": "uuid"

}

L'evento rappresenta un fatto già avvenuto.

Non costituisce un comando e non determina autonomamente una transizione
del Learning Object.

================================================================================
Event Persistence
=================

La prima implementazione utilizza un Transactional Event Record persistence
coerente con la Persistence Implementation Specification.

Il Transactional Event Record è un artefatto infrastrutturale destinato alla
successiva pubblicazione degli eventi.

Non costituisce parte del Repository di conoscenza e non introduce eventi
operativi nel Persistence Model del Repository.

PostgreSQL Transactional Event Record Table

Tabella:

event_records

Campi:

id

UUID primary key

event_type

VARCHAR

event_source

VARCHAR

aggregate_type

VARCHAR

aggregate_id

UUID

version

VARCHAR

payload

JSONB

occurred_at

TIMESTAMP

published_at

TIMESTAMP nullable

created_at

TIMESTAMP

metadata

JSONB nullable

Vincoli:

* event_type obbligatorio;
* event_source obbligatorio;
* aggregate_id obbligatorio;
* version obbligatoria;
* payload obbligatorio;
* event_source deve essere preservato per la successiva pubblicazione;
* version deve essere preservata per la successiva pubblicazione e
  interpretazione;
* un Transactional Event Record è immutabile dopo la creazione;
* published_at può essere valorizzato solo per indicare l'avvenuta
  pubblicazione.

Il Transactional Event Record viene creato nella stessa transazione che
persiste la modifica di dominio che ha prodotto l'evento.

La sua persistenza è separata dalla persistenza delle entità del Repository.

La pubblicazione verso consumer esterni avviene successivamente.

Il Transactional Event Record non modifica il perimetro del Persistence Model:
gli eventi operativi non diventano entità del Repository e non fanno parte
del modello persistente della conoscenza.

================================================================================
Error Handling
==============

La mancata pubblicazione evento non deve compromettere la consistenza del
dominio.

Prima implementazione:

Transactional Event Record

L'evento viene registrato nella stessa transazione
dell'operazione di dominio/applicativa.

La pubblicazione verso consumer esterni avviene successivamente
senza rendere la disponibilità del consumer una precondizione
per la consistenza del dominio.

Successivamente:

Outbox Pattern
