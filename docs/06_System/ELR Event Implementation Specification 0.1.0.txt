================================================================================
Scopo
=====

La ELR Event Implementation Specification definisce la prima implementazione
del modello eventi dell'English Learning Repository.

Gli eventi rappresentano fatti avvenuti nel sistema.

Gli eventi:

* non comandano il sistema;
* non sostituiscono le API;
* non contengono logica applicativa.

================================================================================
Event Principles
================

EVENT-IMPLEMENTATION-001 — Facts Only

Gli eventi descrivono eventi già completati.

EVENT-IMPLEMENTATION-002 — Immutable Events

Un evento pubblicato non viene modificato.

EVENT-IMPLEMENTATION-003 — Domain Origin

Gli eventi significativi originano dal dominio o dall'application layer.

EVENT-IMPLEMENTATION-004 — Loose Coupling

I consumer non devono conoscere il produttore interno dell'evento.

================================================================================
Event Envelope
==============

Ogni evento utilizza una struttura comune coerente con l'ELR Event Model
Specification:

{

"event_id": "uuid",

"event_type": "string",

"event_source": "string",

"entity_id": "uuid",

"entity_type": "string",

"timestamp": "datetime",

"version": "integer",

"payload": {}

}

event_id identifica univocamente l'evento.

event_type identifica il tipo di fatto rappresentato.

event_source identifica il componente che ha prodotto l'evento.

entity_id identifica l'aggregate o l'entità a cui il fatto si riferisce.

entity_type identifica il tipo dell'aggregate o dell'entità.

timestamp identifica l'istante di registrazione dell'evento.

version identifica la versione dello schema dell'evento.

payload contiene esclusivamente le informazioni necessarie a rappresentare
il fatto avvenuto.

================================================================================
LearningObjectCreated
=====================

Descrizione:

Un nuovo Learning Object Candidate è stato creato.

Producer:

LearningObjectService

Payload:

{

```
"learning_object_id": "uuid",

"anchor_id": "uuid",

"lifecycle_status": "Candidate"
```

}

================================================================================
LearningObjectSubmitted
=======================

Descrizione:

Un Learning Object è stato inviato a revisione.

Producer:

LearningObjectService

Payload:

{

```
"learning_object_id": "uuid",

"previous_lifecycle_status": "Candidate",

"new_lifecycle_status": "Proposed"
```

}

================================================================================
ChangeProposalApproved
======================

Descrizione:

Una Change Proposal è stata approvata dalla Learning Review secondo
le regole del Review e del Lifecycle Model.

Producer:

LearningReview / Application Service

Payload:

{

"change_proposal_id": "uuid",

"learning_object_id": "uuid",

"review_id": "uuid"

}

L'evento rappresenta un fatto già avvenuto.

Non costituisce un comando e non determina autonomamente una transizione
del Learning Object.

================================================================================
ChangeProposalRejected
======================

Descrizione:

Una Change Proposal è stata rifiutata dalla Learning Review.

Producer:

LearningReview / Application Service

Payload:

{

"change_proposal_id": "uuid",

"learning_object_id": "uuid",

"review_id": "uuid",

"reason": "string"

}

L'evento rappresenta un fatto già avvenuto.

Non costituisce un comando e non determina autonomamente una transizione
del Learning Object.

================================================================================
LearningObjectUpdated
=====================

Descrizione:

Una nuova versione è stata creata.

Payload:

{

```
"learning_object_id": "uuid",

"new_version": 2
```

}

================================================================================
Error Handling
==============

La mancata pubblicazione evento non deve compromettere la consistenza del
dominio.

Prima implementazione:

Transactional Event Record

L'evento viene registrato nella stessa transazione
dell'operazione di dominio/applicativa.

La pubblicazione verso consumer esterni avviene successivamente
senza rendere la disponibilità del consumer una precondizione
per la consistenza del dominio.

Successivamente:

Outbox Pattern
