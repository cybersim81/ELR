================================================================================
Scopo
=====

La ELR Persistence Implementation Specification definisce la prima
implementazione del livello di persistenza dell'English Learning Repository.

Il documento traduce il modello dominio in strutture persistenti mantenendo:

* integrità della conoscenza;
* continuità storica;
* tracciabilità delle modifiche;
* separazione tra dominio e database.

================================================================================
Persistence Principles
======================

PERSISTENCE-IMPLEMENTATION-001 — Domain Independence

La persistenza non modifica il significato delle entità dominio.

PERSISTENCE-IMPLEMENTATION-002 — Historical Preservation

Le modifiche non cancellano la storia precedente.

PERSISTENCE-IMPLEMENTATION-003 — Explicit Versioning

Ogni variazione significativa genera una nuova versione.

PERSISTENCE-IMPLEMENTATION-004 — Audit Traceability

Le operazioni rilevanti devono essere ricostruibili.

================================================================================
Repository Pattern
==================


I repository espongono operazioni coerenti con le responsabilità
del dominio e della persistenza.

---------------------------------------------------------------------------
LearningObjectRepository
---------------------------------------------------------------------------
Metodi:

* `save()`
* `find_by_id()`
* `find_active()`
* `find_history()`

Responsabilità:

Persistenza e recupero dei Learning Object.

---------------------------------------------------------------------------
VersionRepository
---------------------------------------------------------------------------

Metodi:

* `create_version()`
* `get_versions()`

Responsabilità:

Persistenza e recupero delle Version.

---------------------------------------------------------------------------
AuditRepository
---------------------------------------------------------------------------

Metodi:

* `record_audit()`
* `find_audit_records()`

Responsabilità:

Persistenza e recupero degli AuditRecord.

---------------------------------------------------------------------------
EventRecordRepository
---------------------------------------------------------------------------

Metodi:

* `save_event_record()`
* `find_pending_events()`
* `mark_published()`

Responsabilità:

Persistenza e gestione dei Transactional Event Record destinati
alla successiva pubblicazione.

`EventRecordRepository` non pubblica direttamente gli eventi e non
gestisce gli AuditRecord.


================================================================================
Transaction Rules
=================

Ogni modifica persistente deve essere transazionale.

Esempio:

Approve Learning Object:

1. verifica lo stato corrente;
2. esegue la transizione di lifecycle autorizzata;
3. risolve l'azione di versioning secondo le regole del dominio;
4. persiste lo stato risultante;
5. registra l'AuditRecord;
6. registra eventuali Transactional Event Record;
7. conferma il commit.

Il Transactional Event Record deve essere creato
nella stessa transazione che persiste la modifica
di dominio che ha prodotto l'evento.

La pubblicazione dell'evento è un'operazione successiva
e non fa parte della transazione di dominio.

================================================================================
Persistence Validation
======================

La persistenza deve impedire:

* Learning Object senza Anchor;

* versione duplicata;

* lifecycle_status non valido;

* modifica di snapshot storici;

* eliminazione della storia.

================================================================================
Migration Strategy
==================

Le modifiche allo schema database devono utilizzare:

Alembic migrations

Ogni modifica deve essere:

* versionata;
* reversibile;
* tracciabile.
