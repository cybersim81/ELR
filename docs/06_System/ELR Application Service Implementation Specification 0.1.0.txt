================================================================================
Scopo
=====

La ELR Application Service Implementation Specification definisce il livello
applicativo dell'English Learning Repository.

L'Application Layer coordina:

* API requests;
* casi d'uso;
* regole dominio;
* persistenza;
* audit.

L'Application Layer NON contiene:

* logica cognitiva;
* schema database;
* dettagli HTTP.

================================================================================
Application Principles
======================

APPLICATION-001 — Use Case Ownership

Ogni operazione applicativa rappresenta un caso d'uso esplicito.

APPLICATION-002 — Domain Authority

Le regole di dominio rimangono nel Domain Layer.

APPLICATION-003 — Transaction Control

Le operazioni applicative definiscono il confine transazionale.

APPLICATION-004 — Process Coordination

L'Application Layer coordina componenti senza sostituirne la responsabilità.

Application Services

================================================================================
Learning Object Service
=======================

Responsabilità:

Gestire i casi d'uso relativi ai Learning Object.

Metodi:

create_candidate()

Crea un nuovo Learning Object nello stato Candidate.

submit_for_review()

Avvia il processo di revisione.

approve_learning_object()

Applica approvazione autorizzata.

reject_learning_object()

Gestisce rifiuto della proposta.

get_learning_object()

Recupera conoscenza persistente.

get_history()

Recupera version history.

================================================================================
Transaction Rules
=================

Ogni use case di modifica deve essere atomico.

Esempio:

Approve:

BEGIN TRANSACTION

* validate;
* transition;
* version creation;
* persistence;
* audit.

COMMIT

In caso di errore:

ROLLBACK

================================================================================
Dependency Rules
================

Application Layer può dipendere da:

* Domain Layer;
* Repository Interface;
* Services tecnici.

Application Layer NON può dipendere da:

* FastAPI;
* SQLAlchemy;
* PostgreSQL;
* framework infrastrutturali.

================================================================================
Error Handling
==============

Gli Application Services traducono errori dominio in errori applicativi.

Esempi:

InvalidStateTransition

EntityNotFound

UnauthorizedOperation

ValidationFailure
