================================================================================
Scopo
=====

Questo documento definisce il piano operativo per realizzare il primo
incremento funzionante dell'English Learning Repository.

Il piano traduce le specifiche architetturali in una sequenza implementativa
controllata.

================================================================================
Implementation Goal
===================

Nome incremento:

ELR Core Repository v0.1

Obiettivo:

Realizzare un sistema capace di:

* creare Learning Object;
* gestire lifecycle;
* conservare versioni;
* mantenere audit;
* esporre API;
* pubblicare eventi base.

================================================================================
Implementation Strategy
=======================

L'implementazione segue il principio:

Domain First

Ordine:

1. Domain Model + Lifecycle/Versioning Rules

2. Persistence

3. Application Services

4. API

5. Events

6. Security

7. Integration Testing

================================================================================
Milestone 1 — Project Foundation
================================

Obiettivo:

Creare struttura software iniziale.

Deliverables:

* repository codice;
* ambiente Python;
* gestione dipendenze;
* configurazione test.

Struttura:

elr/

```
app/


tests/


migrations/
```

Criterio completamento:

Il progetto viene eseguito localmente.

================================================================================
Milestone 2 — Domain Implementation
===================================

Obiettivo:

Implementare entità dominio.

Componenti:

* Anchor;
* LearningObject;
* KnowledgeStatement;
* KnowledgeCategory;
* Version;
* AuditRecord.

Criteri:

* entità indipendenti;
* regole dominio testate;
* lifecycle implementato;
* versioning e invarianti delle versioni implementati.

================================================================================
Milestone 3 — Persistence Layer
===============================

Obiettivo:

Persistenza PostgreSQL.

Componenti:

* database schema;
* migrations;
* repositories.

Criteri:

* CRUD base;
* version persistence;
* version history preservation;
* audit persistence;
* Transactional Event Record persistence;
* historical versions are immutable.

================================================================================
Milestone 4 — Application Layer
===============================

Obiettivo:

Implementare casi d'uso.

Use Case:

* create candidate;
* submit review;
* approve;
* reject;
* retrieve;
* history.

Criteri:

* transaction boundary;
* error handling;
* domain protection.

================================================================================
Milestone 5 — API Layer
=======================

Obiettivo:

Esporre API REST.

Endpoint iniziali:

/learning-objects

/categories

/health

Criteri:

* API funzionanti;
* validazione;
* mapping corretto.

================================================================================
Milestone 6 — Event Layer
=========================

Obiettivo:

Implementare eventi.

Eventi:

LearningObjectCreated;
LearningObjectSubmitted;
LearningObjectUpdated;
ChangeProposalApproved;
ChangeProposalRejected;
ChangeProposalModified.

Criteri:

Transactional Event Record persistiti;
eventi tracciabili;
eventi prodotti dal flusso applicativo in seguito a transizioni
o modifiche di dominio significative;
gli eventi di Review rappresentano le decisioni sulla Change Proposal
e non costituiscono Lifecycle Events del Learning Object;
l'API non genera direttamente eventi di dominio.

================================================================================
Milestone 7 — Security Layer
============================

Obiettivo:

Applicare controllo accessi.

Implementare:

* Identity Context;
* Role checks;
* Authorization middleware.

Criteri:

* operazioni protette;
* audit attore.

================================================================================
Definition of Done
==================

ELR Core Repository v0.1 è completato quando:

* un Learning Object può essere creato;
* può attraversare lifecycle;
* può essere versionato;
* può essere recuperato via API;
* ogni modifica significativa è auditata;
* gli eventi relativi a transizioni o modifiche di dominio significative sono prodotti dal flusso applicativo;
* i test principali passano.
