================================================================================
Scopo
=====

La ELR API Implementation Specification definisce il primo livello API
implementativo dell'English Learning Repository.

Le API espongono capacità applicative senza esporre direttamente:

* database;
* entità interne;
* dettagli infrastrutturali.

================================================================================
API Principles
==============

API-IMPLEMENTATION-001 — Domain Protection

Le API non modificano direttamente il dominio.

API-IMPLEMENTATION-002 — Explicit Operations

Ogni operazione rappresenta un caso d'uso esplicito.

API-IMPLEMENTATION-003 — Lifecycle Compliance

Ogni modifica deve rispettare il Lifecycle Model.

API-IMPLEMENTATION-004 — Traceable Actions

Ogni modifica deve produrre audit.

================================================================================
Learning Object API
===================

================================================================================
POST /api/v1/learning-objects
=============================

Scopo:

Creare un nuovo Learning Object Candidate.

Request:

{
"anchor_id": "uuid",
"statement": "text",
"category_id": "uuid"
}

Response:

{
"id": "uuid",
"state": "Candidate"
}

Regole:

* crea solo Candidate;
* non rende la conoscenza attiva;
* genera AuditRecord.

================================================================================
GET /api/v1/learning-objects/{id}
=================================

Scopo:

Recuperare un Learning Object.

Response:

{
"id": "uuid",
"state": "Active",
"version": 1
}

================================================================================
Security Boundary
=================

Le API devono applicare:

* autenticazione futura;
* autorizzazione ruolo;
* audit delle operazioni.

Ruoli iniziali:

System

Learning Review

KEP

User

================================================================================
Error Model
===========

Gli errori devono essere espliciti.

Esempi:

INVALID_STATE_TRANSITION

ENTITY_NOT_FOUND

VALIDATION_ERROR

UNAUTHORIZED_OPERATION

================================================================================
Transaction Boundary
====================

Ogni chiamata che modifica conoscenza deve:

1. validare richiesta;

2. eseguire caso d'uso;

3. applicare regole dominio;

4. aggiornare persistenza;

5. generare audit.

================================================================================

* autenticazione reale;

* API Mastery;

* API Exercise;

* API KEP completa;

* GraphQL.
